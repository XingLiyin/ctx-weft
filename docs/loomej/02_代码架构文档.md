context 归位口诀：
- System Prompt ← Capability（我是谁 + 我能做什么）
- Messages      ← Memory（我记得什么）+ Task Spec（我被问什么）+ Knowledge（我看到什么）

## 一、类目录

### loomej-core

#### assembler/（Prompt 组装）

| 类 | 职责 |
|----|------|
| `ContextAssembler` | 流水线入口，并发调度所有 Source，裁剪后交 Composer 拼装，返回 `AssembledPrompt` |
| `ContextRequest` | 组装请求参数（purpose/agent/task/boundCapabilities/skillInstructions 等）|
| `ContextBlock` | 组装中间结果，一个 Source 产出若干 block，含 kind/target/priority/tokenEstimate |
| `ContextSource` | 接口，每个实现负责一类数据（memory/capability/task 等）→ `List<ContextBlock>` |
| `AssembledPrompt` | 最终结果：system 文本 + messages 列表 + tokenCount |
| `AssemblerDeps` | 传给 Source 的依赖包（memory/providers/templateResolver 等），避免 Source 直接依赖 LoopContext |
| `BudgetStrategy` | 接口，按 token 预算裁剪 block 列表 |
| `PriorityBudgetStrategy` | 内置实现，按 priority 从大到小裁剪，priority=0 不可裁 |
| `Composer` | 接口，把裁剪后的 block 列表渲染成最终 prompt |
| `DefaultComposer` | 内置实现，按 system/messages 分组，按 kind 排序拼接 |

#### assembler/sources/（各 ContextSource 实现）

| 类 | 产出 block kind | 注入位置 |
|----|----------------|---------|
| `IdentitySource` | identity | system（Agent 人格描述）|
| `CapabilitySource` | capabilities | system（工具列表 JSON + 技能说明）|
| `TaskSpecSource` | task_spec | messages 末尾（当前任务描述，role=user）|
| `RecentMemorySource` | history | messages（recallRecent 返回的对话历史）|
| `BlackboardSource` | blackboard | messages（父子任务结果、长期背景）|
| `SemanticRecallSource` | recall | messages（语义检索，不支持时返空）|
| `KnowledgeRetrievalSource` | reference | messages（RAG 检索结果）|

#### auth/（权限）

| 类 | 职责 |
|----|------|
| `Authorizer` | 接口，工具调用前过滤允许的 capability 列表 |
| `AllowAllAuthorizer` | 全部放行的默认实现，目前生产使用 |

#### control/（事件重放）

| 类 | 职责 |
|----|------|
| `Reducers` | 纯静态工具类，将 `List<Event>` reduce 成 `RunStateView`；支持全量 reduce 和增量 applyEvents |
| `RunStateView` | 事件重放的结果视图，包含 sessions/tasks/agents 三个 Map |
| `SessionView` | Session 的投影视图（id/status/rootAgentId/templateId 等）|
| `TaskView` | Task 的投影视图（id/status/parentTaskId/assignedAgentId 等）|
| `AgentView` | Agent 的投影视图（id/templateId/loopGuard 等）|
| `Converters` | 把 View 对象转换成 Session/Task/Agent 领域对象（崩溃恢复时用）|

#### events/（事件体系）

| 类 | 职责 |
|----|------|
| `Event` | 不可变事件 record（id/runId/sessionId/taskId/agentId/type/payload/timestamp）|
| `EventBus` | 接口，subscribe/emit/unsubscribe |
| `InProcessEventBus` | 同步内存实现，emit 时在调用方线程上逐一调用所有订阅者 |
| `EventTypes` | 所有事件类型常量（40+ 个字符串常量 + `ALL` 集合）|
| `SubscriptionHandle` | 订阅句柄，持有订阅 key 可用于取消订阅 |

#### llm/（LLM 协议）

| 类 | 职责 |
|----|------|
| `LLMClient` | 接口，`complete(LLMRequest) → Iterator<LLMChunk>`；提供 contextLimit/maxOutputTokens |
| `LLMClientResolver` | 接口，按 accountName+model 动态创建 `LLMClient` |
| `LLMRequest` | LLM 请求（messages/tools/temperature/maxTokens 等）|
| `LLMMessage` | 单条消息（role/content/toolCalls/toolCallId）|
| `LLMChunk` | 流式响应分片（TEXT_DELTA/TOOL_CALL/REASONING_DELTA/USAGE/ERROR）|
| `LLMTool` | 传给 LLM 的工具定义（name/description/inputSchema）|
| `LLMUsage` | token 用量（promptTokens/completionTokens）|
| `ToolCall` | LLM 返回的工具调用（id/name/arguments）|
| `LLMCallError` | LLM 调用错误（code/message）|

#### loop/（循环引擎）

| 类 | 职责 |
|----|------|
| `StepDriver` | 同步驱动 Step 链，负责 cancel 检查、事件 emit、状态 patch 应用、USER_PROMPT ingest |
| `Step` | 接口，`execute(LoopState, LoopContext) → StepOutcome` |
| `StepOutcome` | Step 执行结果（nextStep/statePatch/events/requestPause）|
| `LoopContext` | 单次任务执行的依赖容器 record（assembler/llm/memory/eventBus/capabilityGateway 等 14 个字段）|
| `LoopState` | 单次任务执行的可变状态（session/task/agent/scope/transcript/verdict 等）|
| `CapabilityGateway` | 工具调用中间件：lookup → authorize → execute → audit → memory ingest |
| `InvocationResult` | 单次工具调用结果（invocationId/toolName/content/metadata/isError）|
| `TurnRecord` | 单轮 LLM 调用记录（turn/messagesSent/assistantText/toolCalls/toolResults/usage）|
| `Verdict` | ObserveStep 产出（taskOutcome: success/failed/needs_user_input/active + summary）|
| `EventHelper` | 静态工具类，简化 Step 内 `Event.of(...)` 的构造和 emit |

#### loop/steps/（各 Step 实现）

| 类 | 职责 |
|----|------|
| `ReasonStep` | token 估算 → compact 触发判断 → 能力绑定 → Prompt 组装 |
| `ActStep` | 多轮 LLM 推理 + 工具调用，直到 normal/suspended/max_turns/context_limit |
| `ObserveStep` | 评估 actor 结果，调用 submit_task_assessment，产出 Verdict |
| `FinalizeStep` | 写 OBSERVER_SUMMARY 记忆、发布 Blackboard、更新 Task 状态 |
| `CompactStep` | 调 LLM 生成摘要，调 applyCompact 归档旧记录，重置 loopGuard baseline |
| `SuspendStep` | 将当前任务标记为 SUSPENDED（DAG 等待等特殊场景）|
| `MetadataFillerStep` | 守护步骤：向 LLM 提取 session goal，写入 Session.goal 字段 |

#### orchestrator/（任务调度与协调）

| 类 | 职责 |
|----|------|
| `ProviderRegistry` | 依赖注入容器，持有所有 provider 引用，shell 装配后传给 LoomeJRuntime |
| `TaskManager` | 单 Session 的任务 DAG 调度器，管理队列/running/completed，处理父子恢复 |
| `CapabilityCache` | 按 agentId 缓存 ReasonStep 绑定的能力列表，ActStep 直接查（避免重复 resolve）|
| `HitlManager` | HITL 审批管理，request() 阻塞虚拟线程，approve/reject() 通过 CompletableFuture 解锁 |
| `HitlApproval` | HITL 审批记录（approvalId/status/modifiedArguments 等）|
| `CancelToken` | 协作取消令牌，`cancel()` 设标志位，`raiseIfCancelled()` 抛 CancelledException |
| `ControlCapabilityProvider` | 内置控制工具（submit_task/submit_plan/submit_task_assessment 等），按 session 注册 |
| `SkillExecutorCapabilityProvider` | 技能执行工具（get_skill_files/load_skill_reference/exec_skill_script），懒加载索引 |
| `RunHandle` | 单次任务执行的控制句柄，持有 cancelToken，可订阅事件流、触发取消 |

#### persistence/（事件持久化）

| 类 | 职责 |
|----|------|
| `EventPersister` | EventBus 订阅者，过滤流式事件后 INSERT 到 core_events 表 |
| `SnapshotWriter` | EventBus 订阅者，监听 SessionFinished 写 RunStateView 快照 |

## 二、调用链

### 2.1 创建 Session 到开始执行

```
POST /api/v1/sessions
  └─► SessionController.createSession(request)
        └─► SessionRegistry.createAndStart(request)
              ├─► sessionMapper.insert()                  写 sessions 表
              ├─► taskMapper.insert()                     写 tasks 表（根 Task）
              ├─► runtime.createSession(id, tenantId)
              │     ├─► sessions.put(id, Session)
              │     ├─► buildAndRegisterTaskManager()
              │     │     ├─► new TaskManager(sessionId, eventBus, 4)
              │     │     ├─► tm.setRunner(this::runTask)
              │     │     ├─► tm.setSessionDoneCallback(...)
              │     │     └─► controlProvider.registerSession(id, tm, session)
              │     └─► eventBus.emit(SessionCreated)
              ├─► runtime.submit(sessionId, userPrompt, templateId, extra)
              │     ├─► session.setTemplateId(...)
              │     ├─► eventBus.emit(SessionStatusChanged)
              │     ├─► Task rootTask = Task.builder()...build()
              │     ├─► cancelTokens.put(taskId, new CancelToken())
              │     ├─► taskManager.pushTask(rootTask, null)
              │     │     └─► queue.offer(rootTask)
              │     │           └─► drain()  →  Thread.ofVirtual().start(runTask)
              │     └─► spawnMetadataFillerDaemon(...)     后台填 goal
              └─► 注册 EventBus 订阅者（SessionEntry.onEvent）
```

### 2.2 runTask → StepDriver 主循环

```
LoomeJRuntime.runTask(sessionId, taskId)
  └─► runTaskInternal(session, task)
        ├─► 解析模板（DatabaseTemplateResolver 或默认）
        ├─► 实例化 Agent（id/loopConfig/loopGuard/model）
        ├─► 动态构建 currentSkillIndex（扫描 registry.skillProviders()）
        ├─► 构建 ProviderContext（sessionId/tenantId/taskId/agentId）
        ├─► 构建 CapabilityGateway(capabilityCache, providers, memory, eventBus, authorizer)
        ├─► 构建 LoopContext（assembler/llm/memory/eventBus/ctx/gateway/...）
        ├─► 构建 LoopState（runId/session/task/agent/scope）
        ├─► 构建 StepDriver（steps: reason/act/observe/finalize/compact/suspend）
        ├─► emit TaskStarted, AgentInstantiated, RunStarted
        └─► StepDriver.run(state, ctx)
              ├─► ingestUserPromptIfNeeded()          写 USER_PROMPT 记忆
              └─► while(currentStep != null):
                    ├─► cancelToken.raiseIfCancelled()
                    ├─► emit StepStarted
                    ├─► outcome = step.execute(state, ctx)
                    ├─► state.applyPatch(outcome.statePatch)
                    ├─► emit outcome.events
                    ├─► emit StepCompleted
                    └─► currentStep = outcome.nextStep
```

### 2.3 ReasonStep 执行链

```
ReasonStep.execute(state, ctx)
  ├─► 检查 tokenBudget（session 级预算）
  ├─► memory.recallRecent(scope, COMPACT_COUNT_TYPES, 500)
  │     └─► PostgresMemoryProvider → SELECT memory_records WHERE superseded=false
  ├─► 估算 estimatedTokens（有基线用增量，无基线后面用 prompt.tokenCount）
  ├─► memory.countRecent(scope, DELTA_COUNT_TYPES)
  ├─► 判断是否触发 Compact：
  │     tokenRatio || messageDelta → dispatchCompact()
  │       ├─► 创建 TaskKind.COMPACT 子任务
  │       ├─► task.setStatus(SUSPENDED)
  │       ├─► taskManager.pushTask(compactTask, parentTaskId)
  │       └─► return StepOutcome.done()（nextStep=null）
  ├─► resolveCapabilities(state, ctx, assignedSkill)
  │     └─► 遍历 ctx.capabilityProviders，用 LinkedHashMap 去重
  ├─► capabilityCache.put(agentId, boundCaps)
  ├─► loadSkillInstructions(assignedSkill, ctx)
  │     └─► skillProviderIndex.get(skillName).loadDefinition()
  ├─► ctx.assembler.assemble(contextRequest, budgetTokens)
  │     ├─► 并发调度所有 Source.fetch()
  │     ├─► PriorityBudgetStrategy.apply(blocks, budgetTokens)
  │     └─► DefaultComposer.compose(blocks) → AssembledPrompt
  └─► return StepOutcome.next("act", {assembledPrompt: prompt})
```

### 2.4 ActStep 执行链（单轮）

```
ActStep.execute(state, ctx)
  └─► for turn in 1..maxTurnsPerAct:
        ├─► cancelToken.raiseIfCancelled()
        ├─► emit ActTurnStarted
        ├─► llm.complete(LLMRequest)          返回 Iterator<LLMChunk>
        │     └─► OpenAICompatibleLLMClient（HTTP POST，SSE 流式解析）
        ├─► 消费 chunks：
        │     ├─► TEXT_DELTA → emit LLMTokenStreamed
        │     ├─► TOOL_CALL  → 累积 toolCalls
        │     └─► USAGE      → loopGuard.updateBaseline(promptTokens, msgCount)
        ├─► emit LLMResponseFinished
        ├─► 无 toolCalls → break，nextStep="observe"
        └─► 有 toolCalls → 顺序调用每个工具：
              └─► capabilityGateway.invoke(toolName, args, state, ctx)
                    ├─► capabilityCache.getByName(agentId, toolName)
                    ├─► authorizer.filter(...)
                    ├─► emit CapabilityInvoked
                    ├─► memory.ingest(TOOL_INVOCATION)
                    ├─► provider.invoke(capabilityId, args, ctx)   Iterator<CapabilityEvent>
                    │     └─► BuiltinToolsCapabilityProvider / SpringAiMcpCapabilityProvider
                    │           / ControlCapabilityProvider / ...
                    ├─► 消费 events → emit CapabilityProgress
                    ├─► emit CapabilityFinished / CapabilityFailed
                    ├─► memory.ingest(TOOL_RESULT)
                    └─► 若 metadata["task_suspended"]=true → suspended=true
              ├─► suspended=true → break，nextStep=null
              └─► 追加 tool_results 到 messages，进下一轮
```
