# LoomeJ 持久化设计文档

## 1. 总体架构

持久化层由以下组件构成：

```
PostgreSQL 数据库
  ├─ sessions            会话基础信息
  ├─ tasks               任务基础信息
  ├─ memory_records      对话记忆（摄入/回忆/压缩）
  ├─ hitl_requests       HITL 审批请求
  ├─ core_events         事件溯源日志
  ├─ run_state_snapshots 运行状态快照（加速恢复）
  ├─ skill_sources       远程 skill source 配置
  ├─ llm_accounts        LLM 账号配置
  └─ agent_templates     Agent 模板配置

Flyway 版本管理：src/main/resources/db/migration/V*.sql
MyBatis：接口 + XML mapper，underscore → camelCase 自动转换
```

## 2. 数据库表结构

### 2.1 sessions 表

```sql
CREATE TABLE sessions (
    id              VARCHAR(64)   PRIMARY KEY,
    tenant_id       VARCHAR(64)   NOT NULL DEFAULT 'default',
    status          VARCHAR(32)   NOT NULL DEFAULT 'RUNNING',
    goal            TEXT,
    user_prompt     TEXT,
    template_id     VARCHAR(128),
    root_agent_id   VARCHAR(64),
    token_budget    INTEGER,
    input_tokens    INTEGER       DEFAULT 0,
    output_tokens   INTEGER       DEFAULT 0,
    context_tokens  INTEGER       DEFAULT 0,
    failure_counter INTEGER       DEFAULT 0,
    llm_provider    VARCHAR(128),   -- LLM 账号标识（前端字段名 llm_provider）
    llm_model       VARCHAR(128),
    created_at      TIMESTAMPTZ   NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ   NOT NULL DEFAULT NOW()
);
```

**字段说明**：
- `status`：RUNNING / PAUSED_HITL / INTERRUPTED / SUCCEEDED / FAILED / CANCELED
- `goal`：会话目标（由 MetadataFiller 异步写入）
- `llm_provider`：对应 `llm_accounts.account_name`，用于选择 LLM 提供商
- `token_budget`：会话总 token 预算（0=不限制）
- `failure_counter`：连续失败轮数，用于判断是否终止 session

### 2.2 tasks 表

```sql
CREATE TABLE tasks (
    id                  VARCHAR(64)   PRIMARY KEY,
    session_id          VARCHAR(64)   NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
    parent_task_id      VARCHAR(64),
    kind                VARCHAR(32)   NOT NULL DEFAULT 'REASONING',
    status              VARCHAR(32)   NOT NULL DEFAULT 'PENDING',
    title               VARCHAR(512),
    description         TEXT,
    user_prompt         TEXT,
    process_report      TEXT,
    skill_name          VARCHAR(128),
    creator_agent_id    VARCHAR(64),
    assigned_agent_id   VARCHAR(64),
    share_scope         BOOLEAN       DEFAULT FALSE,
    compact_scope_agent_id VARCHAR(64),
    retry_count         INTEGER       DEFAULT 0,
    max_retries         INTEGER       DEFAULT 0,
    error               TEXT,
    created_at          TIMESTAMPTZ   NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ   NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_tasks_session_id ON tasks(session_id);
```

**字段说明**：
- `kind`：REASONING / COMPACT / METADATA_FILLER
- `status`：PENDING / ACTIVE / SUSPENDED / FINISHED / FAILED / CANCELED
- `skill_name`：分配给该任务的技能名（对应 `TaskSettings.Normal.skillName`）
- `share_scope`：子任务是否共享父任务的 memory scope
- `compact_scope_agent_id`：COMPACT 任务专用，指向要压缩的父 agent scope
- `process_report`：ObserveStep 的任务总结，用于父任务的 `## Current Progress`

### 2.3 memory_records 表

```sql
CREATE TABLE memory_records (
    id          VARCHAR(64)   PRIMARY KEY,
    session_id  VARCHAR(64)   NOT NULL,
    task_id     VARCHAR(64),
    agent_id    VARCHAR(64),
    event_type  VARCHAR(64)   NOT NULL,
    role        VARCHAR(32),
    content     TEXT          NOT NULL,
    topic       VARCHAR(128),
    sequence    BIGINT        NOT NULL,
    superseded  BOOLEAN       NOT NULL DEFAULT FALSE,
    created_at  TIMESTAMPTZ   NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_memory_session_task ON memory_records(session_id, task_id);
CREATE INDEX idx_memory_event_type ON memory_records(event_type);
CREATE INDEX idx_memory_superseded ON memory_records(superseded);
```

**字段说明**：
- `event_type`：USER_PROMPT / LLM_RESPONSE / OBSERVER_SUMMARY / COMPACT_SUMMARY / TOOL_INVOCATION / TOOL_RESULT / BLACKBOARD_PUBLISH
- `role`：user / assistant / system（对应 LLM 消息角色）
- `topic`：黑板发布时的主题（BLACKBOARD_PUBLISH 专用）
- `sequence`：全局递增序列号，用于排序和增量估计
- `superseded`：压缩时旧记录标记为 true，回忆时过滤掉

**PostgresMemoryProvider 关键查询**：

```sql
-- recallRecent（按 scope 过滤，最新 N 条）
SELECT * FROM memory_records
WHERE session_id = ?
  AND (? IS NULL OR task_id = ?)
  AND (? IS NULL OR agent_id = ?)
  AND event_type IN (?)
  AND superseded = false
ORDER BY sequence DESC
LIMIT ?

-- applyCompact（标记旧记录）
UPDATE memory_records SET superseded = true
WHERE session_id = ? AND task_id = ? AND agent_id = ?
  AND superseded = false
  AND id NOT IN (SELECT id FROM memory_records ... ORDER BY sequence DESC LIMIT ?)

-- 插入 COMPACT_SUMMARY
INSERT INTO memory_records(id, session_id, task_id, agent_id, event_type, role, content, sequence, ...)
VALUES (?, ?, ?, ?, 'COMPACT_SUMMARY', 'system', ?, ?, ...)
```


**status 值**：PENDING / APPROVED / REJECTED / MODIFIED / TIMEOUT

### 2.5 core_events 表（事件溯源）

```sql
CREATE TABLE core_events (
    id          VARCHAR(64)   PRIMARY KEY,
    run_id      VARCHAR(64),
    session_id  VARCHAR(64)   NOT NULL,
    task_id     VARCHAR(64),
    agent_id    VARCHAR(64),
    event_type  VARCHAR(128)  NOT NULL,
    sequence    BIGINT,
    payload     JSONB,
    timestamp   TIMESTAMPTZ,
    created_at  TIMESTAMPTZ   NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_core_events_session ON core_events(session_id);
CREATE INDEX idx_core_events_run ON core_events(run_id);
CREATE INDEX idx_core_events_seq ON core_events(session_id, sequence);
```

**说明**：
- 所有非流式 core 事件均写入此表（`EventPersister` 订阅 EventBus）
- 流式事件（LLM_TOKEN_STREAMED、LLM_REASONING_STREAMED）不持久化（高频低价值）
- `payload` 为 JSONB，存储事件的完整 payload Map
- 用于崩溃恢复（`recoverSession()` 从此表重放事件序列）

### 2.6 run_state_snapshots 表（快照）

```sql
CREATE TABLE run_state_snapshots (
    id          SERIAL        PRIMARY KEY,
    session_id  VARCHAR(64)   NOT NULL,
    run_id      VARCHAR(64)   NOT NULL,
    snapshot    JSONB         NOT NULL,
    created_at  TIMESTAMPTZ   NOT NULL DEFAULT NOW(),
    UNIQUE(session_id, run_id)
);
CREATE INDEX idx_snapshots_session ON run_state_snapshots(session_id);
```

**snapshot JSON 结构（RunStateView）**：
```json
{
  "session": { "id": "...", "status": "RUNNING", "tokenUsed": 12000, ... },
  "task": { "id": "...", "status": "SUSPENDED", "title": "...", ... },
  "agent": {
    "id": "...",
    "loopGuard": { "turnsUsed": 3, "contextTokens": 8192, ... }
  },
  "transcript": [...TurnRecord array...],
  "stepName": "reason"
}
```

写入时机：`SnapshotWriter` 订阅 EventBus，收到 `SESSION_FINISHED` 时写入。

## 4. 事件持久化流程

```
EventBus.emit(event)
  │
  ├─ EventPersister.onEvent(event)
  │    if event.type NOT IN [LLM_TOKEN_STREAMED, LLM_REASONING_STREAMED]:
  │      PostgresEventStore.persist(event)
  │      INSERT INTO core_events(id, run_id, session_id, task_id, agent_id,
  │                               event_type, sequence, payload, timestamp)
  │
  └─ SnapshotWriter.onEvent(event)
       if event.type == SESSION_FINISHED:
         snapshot = buildSnapshot(state)
         PostgresEventStore.writeSnapshot(sessionId, runId, snapshot)
         INSERT/UPDATE run_state_snapshots
```

## 5. SSE 事件缓冲与持久化

```
SessionEntry（内存中）：
  sseBuffer: CopyOnWriteArrayList<String>  // SSE JSON 字符串列表
  sseIndex: AtomicInteger                  // 每个连接的读取位置（per-connection）

写入路径：
  EventBus → SessionRegistry.onEvent() → SseEventTranslator.translate()
            → jsonStrings → sseBuffer.addAll()
            → session_sse_events 表写入（可选，用于断线重连）

SSE 推流路径：
  GET /{id}/stream:
    创建 SseEmitter
    从 sseBuffer[currentIndex..] 推送历史事件
    等待新事件（blocking）
    连接断开后保持 sseBuffer，下次重连继续
```

## 6. 崩溃恢复（Recover Flow）

```
应用重启时，SessionRegistry.loadSessionsFromDb()：
  1. SELECT * FROM sessions WHERE status IN ('RUNNING', 'PAUSED_HITL')
  2. 对每个"运行中"的 session：
     entry = SessionEntry.fromDb(row)
     entry.status = "INTERRUPTED"
     UPDATE sessions SET status='INTERRUPTED' WHERE id=?
     注册 EventBus 订阅者

用户点击"恢复"时，POST /{id}/resume：
  1. LoomeJRuntime.recoverSession(sessionId)
  2. 从 run_state_snapshots 加载最新快照
     如无快照：从 core_events 重放事件序列 → 重建 LoopState
  3. 重建 LoopContext（重新创建 cancelToken 等）
  4. 从快照记录的 stepName 重新开始循环
  5. entry.status = "RUNNING"
```
